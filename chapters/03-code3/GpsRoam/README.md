# GPS 漫游（GpsRoam）

Android 端的轻量 GPS 虚拟定位工具。**只有两个功能：录制路线、模拟路线。**

> 用途：自己测试定位类应用。不做分发，纯本机使用，数据不出本机。

---

## 一、两个功能

| 功能 | 做什么 |
|---|---|
| **录制路线** | 揣着手机真实走一遍，停下命名保存，进轨迹库。和运动 App 记一次运动一样。 |
| **模拟路线** | 从轨迹库选一条，调好倍速，按**原始时间轴**原样复现，同时把坐标写进系统定位、盖掉真实 GPS。 |

回放按原始时间轴推进 —— 当时走得快就走得快，路口等灯就停在原地，中途坐下来歇了十分钟也照实复现。
因为数据本来就是真的，**不需要任何「拟真算法」去猜**。

**倍速可以运行中随时改**（1× / 2× / 5× / 10×），点中即生效、不弹确认。
改完只改变之后推进的快慢，当前位置、已走距离、航向都不重置，注入是一条连续的流，不会跳点。
上报出去的速度也会同步变成倍速后的值，位置和速度自洽。

## 二、界面

**总共两个界面，没有第三个。**

### 主屏

只有一个**位置固定**的主按钮，内容随状态换 —— 这样拿着手机走路时盲按也按得准。

| 状态 | 状态名 | 主按钮 | 次按钮 | 倍速行 |
|---|---|---|---|---|
| 空闲 | 空闲（灰） | 开始录制 | 选择轨迹回放（库空时隐藏） | 隐藏 |
| 已选轨迹 | 已选轨迹（灰） | 开始模拟 | 重新录制 | 显示 |
| 录制中 | 录制中（红） | 停止并保存 | 隐藏 | 隐藏 |
| 回放中 | 回放中（蓝） | 暂停 | 停止 | 显示 |
| 已暂停 | 已暂停（黄） | 继续 | 停止 | 显示 |

> 「已选轨迹」的次按钮是**重新录制**：选中一条轨迹后必须还能回到录制，否则除了杀进程没有任何路能再录一条。
> 换轨迹走底部常驻的「轨迹库」入口，不占用次按钮。

**不用的东西直接隐藏，不是置灰** —— 置灰的按钮看着像坏掉，还占注意力。
权限条也只在缺权限时出现，齐了整条消失。

中间是**只读轨迹预览**：起点绿、终点红、当前游标蓝；已走段实线、未走段虚线。
不接任何地图 SDK，把轨迹**自身**的经纬度范围等比铺满控件，只表达两件事 —— 形状对不对、走到哪了。
（它是用来核对「录下来的这条对不对」，不是用来认路的。）

### 轨迹库

每行只有三样：**名字** / 点数 · 里程 · 时长。
点一行 = 选中并回主屏；长按 = 重命名或删除。空库时给一句提示 + 一个「去录制」。

## 三、⚠️ 为什么录制和注入不能同时开

注入的原理是注册一个叫 `gps` 的测试 Provider **顶掉真实 GPS**。
只要它还在，`requestLocationUpdates(GPS_PROVIDER)` 拿到的就是我们自己写进去的假坐标
—— 录出来一条假轨迹，回放还是假的，等于白忙。

所以 App 里做了硬性互斥：一开始录制就自动停掉注入，一开始注入就自动停掉录制。
实现在 `service/WanderService.kt`，两边入口都做了兜底。

## 四、能覆盖到什么程度（先说清楚）

目标是「让手机定位按轨迹走、盖掉系统定位」。分三层看：

**✅ 系统定位本身 —— 能覆盖。**
注入层注册了一个叫 `gps` 的测试 Provider，直接顶掉真实 GPS。
任何走 `LocationManager` 或融合定位取位置的应用，读到的都是我们的坐标。
而且经纬度、速度、航向、精度、时间戳是一整条连贯的 1Hz 数据流，不是静态假值。

**⚠️ 只调 API 拿位置的普通应用 —— 骗得过。**
绝大多数应用就是这么用的。

**❌ 检测得深的 —— 骗不过，也不打算骗。**
1. 系统本身会给模拟位置打标记，目标应用调 `Location.isFromMockProvider()` 一句就能识破。
   金融、支付、网约车类基本都查，绕不过去，也不该绕。
2. **运动类 App（Keep、咕咚、悦跑圈这类）还会读加速度计、陀螺仪、计步器。**
   你人坐着不动、定位却在跑，传感器数据是静止的 —— 轨迹和身体对不上。
   这种不一致比 mock 标记更难藏。
   ⚠️ 这一层**不是权限问题，也不是「再多写点代码」能解决的**：Android 没有伪造传感器的公开 API
   （定位有 `addTestProvider`，传感器没有任何对应物，也没有任何权限能开通这件事）。
   唯一办法是 root 手机 + 注入框架（Frida / LSPosed）hook 每个目标应用的进程 ——
   那不是 App，是另一套设备级工具链。本项目不做。
3. 少数应用用自研定位 SDK 直连基站 / WiFi，不走系统 Provider。

所以结论是：**「让定位按录制轨迹动」这件事本身成立，自己测试、骗过普通应用都没问题；
但「骗过所有定位软件」这个说法别当真**，尤其是运动类和金融类。

## 五、跑起来

### 1. 编译

用 Android Studio 打开 `D:\gr\code3\GpsRoam`。

> ⚠️ 仓库里没有 `gradle-wrapper.jar`（二进制文件不便文本生成）。
> 打开时若提示 wrapper 缺失，选 **Use local Gradle distribution**，或补跑一次 `gradle wrapper`。
> 其余配置（AGP 8.2.2 / Gradle 8.2 / JDK 17）已就绪。

### 2. 授权

**录制只需要「精确定位」权限**，装完就能先测这一步。

要跑模拟（回放）还得多一步：

1. **设置 → 关于手机 → 连点「版本号」7 次**，开启开发者模式
2. **设置 → 系统 → 开发者选项 → 选择模拟位置信息应用 → 选中「GPS 漫游」**

主屏的权限条消失（即两项齐备）才说明可以开始。**这个授权每次重装 App 都要重新选。**
而且实测确认：**手机重启后这项授权也会失效**，重启后要重新选一次（权限弹窗不用再点，只有模拟位置授权会掉）。

### 3. 实测记录（2026-09-24，Android 14 x86_64 模拟器）

已在本机模拟器上完整跑通一遍，以下是实测数据，不是纸面推断：

| 验证项 | 结果 |
|---|---|
| 编译 | ✅ `assembleDebug` 通过（修掉 2 处编译错误后） |
| 录制 | ✅ 喂真实 GPS 走 245 m，录出 52 个点 · 2:18，保存对话框正常，保存后自动选中 |
| 回放注入 | ✅ `dumpsys location` 显示 `gps provider [mock]`，坐标 1Hz 连续推进，速度/航向/精度齐全 |
| 覆盖范围 | ✅ **passive provider 也在转发** —— 其他 App 读定位拿到的就是注入坐标 |
| 倍速线性 | ✅ 5× 全程 28.6 s（理论 27.6）、10× 15.1 s（理论 13.8），偏差 ≈1 s 是测试本身的开销 |
| 暂停 | ✅ 暂停 6.5 s 坐标位移 **0.0000 m**，完全冻结 |
| 停止后 | ✅ mock provider override 被拆除，系统定位恢复真实 GPS |
| 崩溃 | ✅ 无（日志里唯一的 FATAL 来自测试工具 uiautomator 自身） |

截图在 `screenshots/`。

> ⚠️ 已知且**不修**的行为：位置带着 `mock` 标记（`isFromMockProvider()` 能识破），
> 这是系统行为，见第四节的能力边界。

### 3. 第一次建议这么测

1. 到**空旷处**（室内、地下车库收不到 GPS）
2. 点「开始录制」→ 走几十米 → 点「停止并保存」→ 起个名字
3. 看一眼轨迹库里的点数和里程，明显不对（比如站在屋里录出 0 点）就重录
4. 主屏点「开始模拟」，先把倍速设成 **5×** 快速看一遍，确认游标走的形状和你走的一致
5. 再改成 1× 走一遍，这才是真正要用的

## 六、代码结构

```
app/src/main/java/com/gpsroam/
├─ MainActivity.kt                  主屏：录制 / 模拟两个功能的全部交互与状态机
├─ coord/
│   ├─ LatLng.kt                    统一坐标类型
│   ├─ GeoMath.kt                   距离、航向、插值
│   └─ CoordinateConverter.kt       WGS-84 / GCJ-02 / BD-09 三向互转（当前无调用方，见下）
├─ data/
│   ├─ RecordedTrack.kt             录制轨迹模型（含每个点的时间偏移）
│   └─ TrackStore.kt                轨迹落盘（filesDir/tracks/，不联网）
├─ engine/
│   ├─ RoutePlan.kt                 ★ 时间轴推进；时间轴不合法时退回匀速
│   └─ WanderEngine.kt              ★ 引擎：倍速可运行中改，progress 按实际里程算
├─ record/
│   └─ TrackRecorder.kt             ★ 真实 GPS 采集（抽稀 + 静止补点 + 假点过滤）
├─ mock/
│   ├─ MockPermission.kt            模拟位置权限检测
│   └─ MockLocationInjector.kt      ★ 注入层：写坐标给系统
├─ service/
│   └─ WanderService.kt             ★ 前台服务：注入 / 录制两种互斥模式 + 通知栏控制
└─ ui/
    ├─ TrackPreviewView.kt          只读轨迹预览（自绘，不依赖任何地图 SDK）
    └─ TrackLibraryActivity.kt      轨迹库
```

**为什么录制轨迹单独一套存储**：量级。一条录制轨迹动辄几千个采样点，
全塞进 SharedPreferences 每次读写都要整体序列化。
所以走文件（`filesDir/tracks/`，索引与明细分开，列表页不必把几万个坐标读进内存）。

**关于 `CoordinateConverter.kt`**：现在没有任何调用方 —— 录制出来的坐标本来就是 WGS-84，
回放也是原样写回去，全程不需要转换。留着是因为唯一可能需要它的情况是
「从高德/百度地图复制一个坐标粘进来」，那时不做转换会**偏几百米**。
如果你确定不会有这个需求，删掉它也不影响任何功能。

## 七、常见问题

**Q：录了半天一个点都没有**
状态行会直接提示「还没收到定位，到空旷处试试」。原因通常是：
1. 在室内/地下，收不到 GPS —— 到空旷处再试。
2. 系统位置服务被关了。
3. 确认不是一边注入一边录（App 会自动互斥，但如果你手动开过注入又忘了停，先停止注入）。

**Q：录制轨迹的点很稀**
抽稀阈值是「不到 4 米不记」。站着不动只有 GPS 漂移，被过滤掉是正常的，走起来就会密集记录。
但**原地停留不会真的空白** —— 每 10 秒会补一个位置不变的点，
这样回放时「等红灯」是真的停住，而不是被插值成缓慢前进。

**Q：回放走得太快 / 太慢**
倍速不是 km/h。`1×` 就是当时走多快就多快，`2×` 是两倍速。载入轨迹后先看一眼状态行的「均速」。

**Q：点开始提示「还没授权模拟位置」**
录制不需要它，但**模拟需要**。没在开发者选项里选中本应用。

**Q：别的 App 还是显示真实位置**
1. 金融、支付、网约车类会检测 `Location.isFromMockProvider()`，这属于目标应用的主动校验，
   本工具无法绕过，也不打算绕过。
2. 少数 App 用自研定位 SDK 直连基站/WiFi，不走系统 Provider。可试开关一次飞行模式重置定位会话。

**Q：走一半停了**
国产 ROM 后台管理激进。**设置 → 应用管理 → GPS 漫游 → 省电策略** 设为「无限制」，并允许自启动。
回放时通知栏有「暂停 / 停止」按钮，不用掏手机开 App。

**Q：通知栏没有那两条按钮 / 看不到通知**
Android 13+ 需要在弹窗里允许通知权限（第一次开始时就会问）。不给的话服务照常跑，只是通知看不到。

**Q：数据会上传吗？**
不会。轨迹都只写在本机（`filesDir/tracks/`），**不联网、不上传、不要存储权限**。

## 八、边界与声明

- 本工具**仅用于自己测试定位类应用**，不得用于考勤打卡作弊、游戏外挂、刷单、伪造物流轨迹或任何欺诈行为。
- 定位数据全部本地处理，不联网、不上传、不收集。
- 不针对特定应用的检测机制做对抗性适配。
- 不伪造传感器数据（加速度计 / 陀螺仪 / 计步器）。Android 没有对应的公开 API，
  唯一路径是 root + 进程注入，超出本项目（一个普通 App）的能力范围。
- 轨迹预览为示意画布，不含任何地图数据；本项目不接入任何地图 SDK。
